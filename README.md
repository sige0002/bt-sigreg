# 撮影条件をまたぐ交差継続予測によるマルチタスクLeWM

**Crossed Continuation Prediction across Visual Conditions for Multi-Task LeWorldModel**

更新日：2026-09-05  
状態：研究仮説・アルゴリズム設計。LeWMへの接続実装、学習、実機検証は未実施。性能向上、頑健性、新規性、SOTA達成は未確認。

> **研究の中心：複数タスクの経験を一つの軽量LeWMへ統合し、現在の操作対象だけでなく後続操作に必要な状態情報も保持する。さらに、照明・背景・カメラ条件だけが変わっても、同じ物理的な未来へ対応付けられる表現と予測器を学ぶ。**

## 1. まず、何をするアルゴリズムなのか

次の三つを同時に学習する。

| 比較 | 学んでほしいこと |
|---|---|
| 同じ操作を、異なる物体配置から実行した | 初期状態の違いに応じた未来を予測する |
| 同じ初期状態から、異なる操作を実行した | 行動による結果の違いを予測する |
| 同じ物理的な出来事を、異なる照明・視点で撮影した | 撮影条件が違っても同じ結果へ対応付ける |

一文では、**物理状態・行動による違いは残し、撮影条件だけの違いには影響されにくくする学習**である。

```text
複数タスクのロボット経験
          │
          ▼
初期状態 × 実際の行動列 を交差させて実行
          │
          ▼
同じ物理軌道を、照明・カメラを変えて観測
          │
          ▼
撮影条件①の現在 ＋ 行動列
          │
          ▼
一つの共有LeWMで未来を予測
          │
          ▼
撮影条件②の実測未来と比較
          │
          ├─ 対応する未来へ近づける
          └─ 物理的に異なる未来とは取り違えない
```

**潜在表現をタスクごとに別クラスタへ押し込む方法ではない。** 目的は、同じ世界モデルを複数の操作とその組み合わせに再利用することにある。

## 2. LeWMのどこを維持し、どこを変えるか

LeWMは画像から潜在状態を作り、行動を条件に未来の潜在状態を予測する。原論文の学習は、未来潜在予測とSIGRegの二項からなる。[1]

本提案の維持・変更点は以下のとおり。

| 要素 | 本提案 |
|---|---|
| 画像エンコーダ | 全タスクで共有する |
| 行動エンコーダ | 全タスクで共有する |
| 行動条件付き予測器 | 一つの共有予測器を使う |
| 潜在空間での自己回帰予測 | 維持する |
| 画像再構成器・行動復号器 | 新設しない |
| タスクID | データの均衡化・記録・評価に使い、予測器へは入れない最小案 |
| SIGReg | 本命候補では実測未来の識別損失へ置換する |
| 潜在ベクトルの長さ | 正規化を追加する。元LeWMと完全同一ではない |
| 学習時の未来展開 | 複数時刻先まで比較する |
| 計画器 | 比較手法間で同じCEM等を使う |
| Goal重みネットワーク・成功判定器 | 今回の本命には含めない |

**「LeWMを全く変えない」ではなく、「共有の行動条件付き予測構造を維持し、学習課題と正則化、潜在正規化を変更する」が正確である。**

SIGRegを外せば自動的に良くなるとは仮定しない。SIGReg併用版も比較する。

## 3. 赤・青キューブによる具体例

二つの初期状態を用意する。

- 初期状態1：赤の位置は固定、青は左。
- 初期状態2：赤の位置は固定、青は右。

ロボット姿勢や撮影条件など、変える必要のない要因は可能な範囲でそろえる。

次に二つの行動列を用意する。

- 行動列1：赤のある位置へ操作する制御値の列。
- 行動列2：青のある位置付近へ操作する制御値の列。

**行動列は言語命令ではなく、実際の関節・手先・グリッパ指令である。各列について同一の制御値を両方の初期状態から実行する。** 一方で空振りしてもよく、その結果を実測する。

|  | 行動列1 | 行動列2 |
|---|---|---|
| 初期状態1 | 実測未来 Y11 | 実測未来 Y12 |
| 初期状態2 | 実測未来 Y21 | 実測未来 Y22 |

赤を動かした後も青の位置が違えば、Y11とY21は異なる。したがって、赤を操作する場合でも青の位置を保持しないと、この二つを識別して予測できない。

同じ初期状態からの異なる行動結果も比較するため、行動を無視する解にも代償を与える。

**単に別タスクの軌道をランダムに混ぜるだけでは、この対応表は作れない。** 対応する分岐実験が必要である。

## 4. 照明・背景・画角への頑健性を組み込む

上の四つの物理軌道について、撮影条件を二種類用意する。

| 物理的な実験 | 撮影条件① | 撮影条件② |
|---|---|---|
| 初期状態1＋行動列1 | 明るい・正面 | 暗い・斜め |
| 初期状態1＋行動列2 | 明るい・正面 | 暗い・斜め |
| 初期状態2＋行動列1 | 明るい・正面 | 暗い・斜め |
| 初期状態2＋行動列2 | 明るい・正面 | 暗い・斜め |

各行の左右は、**同じ時刻・同じ物理状態の別の観測**である。

```text
撮影条件①の初期状態 ＋ 行動列
                │
                ▼
             共有LeWM
                │
                ▼
             予測未来
                │
                ├─ 撮影条件②のY11
                ├─ 撮影条件②のY12
                ├─ 撮影条件②のY21
                └─ 撮影条件②のY22

対応する未来が正解。
候補間で撮影条件はそろえるため、明るさだけでは選べない。
```

①から②だけでなく、②から①も学習する。

### 4.1 撮影条件の割り当て

一つの対応表内では、同じ観測条件をすべてのマスへ適用する。入力側と教師側では異なる条件を選ぶ。条件は表ごとにランダム化し、特定の物体位置・行動・タスクと固定対応させない。

照明や背景の変更だけでマスを識別できるデータにしてはいけない。実験番号、マス番号、教師候補の番号も、エンコーダや予測器へ渡さない。候補順序はランダムに並べ替え、その際は正解対応も一緒に更新する。

入力の短い履歴内では、最初は同じカメラ・照明を保つ。カメラが時間的に移動する場合は、別の難しい評価条件として扱う。

### 4.2 実測・再描画

シミュレーションでは、分岐操作を実行して物理軌道を保存し、その保存状態を異なる照明・カメラで再描画する。レンダリングだけを変える場合には、同じ操作を物理的に再実行する必要はない。

実機では同期した複数カメラや意味を壊さない画像拡張が候補になる。ただし、画像の切り抜きは一般に三次元のカメラ移動や遮蔽変化を再現しない。

複数視点を使った世界モデル表現学習には先行研究があり、視覚条件を変えて学習すること自体を新規性とはしない。[3]

## 5. 区別すべき変化と、同一視してよい変化

| 変化 | 初期実験での扱い |
|---|---|
| 照明強度・露出・影 | 物体識別や状態判定が可能な範囲で対応付ける |
| 操作に無関係な壁紙・背景模様 | 物理状態を変えない限り対応付ける |
| カメラ位置・角度・焦点距離 | 必要な情報が各視点から観測できる範囲で対応付ける |
| 青い物体の実際の位置 | 赤の操作中でも別の状態として保持する |
| 対象物の色・種類 | タスクで識別に必要なら消さない |
| 摩擦・重量・接触状態 | 行動結果を変えるため、撮影外乱として消さない |
| 完全遮蔽・画面外・深刻な露出飽和 | 同じ潜在状態への一致を無条件には要求しない |

赤いキューブを青く変える画像拡張は、「赤を取る」という意味を変える。強い拡張ほど良いとは限らない。

**背景と、現在は操作していない物体を混同しない。** 後者は後続タスクで必要になる可能性がある。

## 6. 記号とデータ単位

一つの対応表をグループ g とする。

| 記号 | 意味 |
|---|---|
| Ns | 初期状態の数。最小案では2 |
| Na | 行動列の数。最小案では2 |
| B = Ns × Na | 表内の物理軌道数。最小案では4 |
| b = (i,m) | 初期状態iと行動列mに対応するマス |
| v, w | 入力側・教師側の撮影条件 |
| m_ctx | 予測器へ渡す最大観測履歴長 |
| H | 比較するモデルステップ先の距離 |
| U_b | マスbで実際に実行した未来の行動列 |
| o(g,b,t,v) | 物理軌道bの時刻tを条件vで観測した画像 |
| D | 潜在次元。最初は192を候補とする |

以下の数式では、読みやすさのためグループgを省略する。異なるグループの未来を自動的にすべて負例にする設計ではない。

同じ行動列mは、初期状態iが変わっても同じ制御値である。初期状態ごとに必要な過去の観測・実行行動履歴も保存する。

**モデルの1ステップと実制御の1ステップは区別する。** 行動ブロックを使う場合は、その長さ、画像間隔、制御周期、行動の正規化統計を全手法で固定・記録する。

## 7. 共有LeWMと潜在正規化

画像エンコーダEには、画像特徴を予測用潜在表現へ写す投影器も含める。行動エンコーダをA、潜在予測器をFとする。

本案では、スケールを無制限に大きくして距離を操作することを抑えるため、

$$
N(x)=\frac{x}{\max(\|x\|_2,\varepsilon)}
$$

を使う。

$$
z_t^{(v)}=N(E_\theta(o_t^{(v)}))
$$

$$
u_t=A_\phi(a_t)
$$

$$
\hat z_{t+1}^{(v)}
=N\!\left(F_\psi(z_{t-m_{ctx}+1:t}^{(v)},u_{t-m_{ctx}+1:t})\right)
$$

履歴は存在する範囲で取り、以後は予測した潜在状態を再入力する。未来展開の各ステップで正規化し、学習と推論で扱いをそろえる。

撮影条件vの初期履歴と、実測した行動列U_bから得たHステップ先の予測を、

$$
q_{b,H}^{(v)}=\operatorname{Rollout}_{F,A}(z_{b,\mathrm{history}}^{(v)},U_b;H)
$$

とする。対応する実測未来を、同じEで

$$
y_{b,H}^{(w)}=N(E_\theta(o_{b,H}^{(w)}))
$$

へ変換する。

### 正規化についての注意

これは分布のガウス化でも共分散の等方化でもない。ただし非ゼロのベクトル長をそろえる幾何的制約はある。厳密なゼロベクトルはこの処理だけでは非ゼロにならない。

正規化前のノルム、ゼロ近傍の頻度、勾配、計画性能を監視する。「正規化だけを追加したLeWM」も対照条件にする。

最小案では、教師側の別エンコーダ、EMA、勾配停止を必須にしない。教師側にも同じEを通じて勾配を流す。実際の安定性は検証対象であり、後から別方式を採用した場合は実験条件の変更として明示する。

## 8. 損失1：撮影条件をまたぐ未来予測

入力の見え方vと異なる見え方wで、対応する実測未来へ近づける。

$$
\mathcal L_{\mathrm{pred}}^{v\to w,H}
=\frac1B\sum_{b=1}^{B}
\left\|q_{b,H}^{(v)}-y_{b,H}^{(w)}\right\|_2^2
$$

例えば「明るい・正面」の現在から予測し、「暗い・斜め」の実測未来の潜在表現と比べる。

画像自体を生成・再構成するのではない。正解の未来潜在表現との対応を学習する。

**異なる撮影条件でも同じ物理結果に対応させることが狙いだが、有限の予測課題だけで、すべての観測の完全な視点不変性が保証されるわけではない。**

---

## 9. 損失2：対応表全体から実測未来を識別する

同じグループ・同じ未来時刻H・同じ教師側撮影条件wの未来候補を使う。

$$
s_{bc}^{v\to w,H}
=-\frac{\left\|q_{b,H}^{(v)}-y_{c,H}^{(w)}\right\|_2^2}{\tau}
$$

未来がすべて区別すべき状態なら、

$$
\mathcal L_{\mathrm{cross}}^{v\to w,H}
=-\frac1B\sum_b
\log\frac{\exp(s_{bb}^{v\to w,H})}
{\sum_{c=1}^{B}\exp(s_{bc}^{v\to w,H})}
$$

とする。温度tauは識別の鋭さを調整するハイパーパラメータである。

### 9.1 なぜ行・列別ではなく表全体を使うのか

二つの初期状態と二つの行動について、次のような表現があり得る。

```text
             行動1    行動2
初期状態1       x        y
初期状態2       y        x
```

各行・各列は区別できても、対角の物理結果を同一視している。行と列だけを別々に比較する損失では、この抜け道が残る。

したがって、**四つの実測未来を一つの候補集合に入れる。**

### 9.2 同じ物理結果になった場合

異なる行動でも同じ結果になる場合がある。飽和した指令、空振り、既に閉じたグリッパへの閉指令などを、行動名だけで負例にしない。

bと実質的に同じ物理的未来に対応する正例集合をP(b,H)とし、

$$
\mathcal L_{\mathrm{cross}}^{v\to w,H}
=-\frac1B\sum_b
\log\frac{
\sum_{c\in\mathcal P(b,H)}\exp(s_{bc}^{v\to w,H})
}{
\sum_{c=1}^{B}\exp(s_{bc}^{v\to w,H})
}
$$

とする。b自身は必ず正例に含める。すべてが同じ結果なら、その比較から識別圧力は生じない。

**ここでの同じ結果とは、「同じタスク成功」ではない。** 箱の左と右は箱入れ成功という意味では同じでも、後で取り出すための状態は異なる。必要な状態差を正例統合で消さない。

正例対応は、保存された物理状態や実観測に基づいて用意する。現在のエンコーダが近く写したことだけを理由に同一としない。部分観測で識別不能な比較は、履歴を増やすか、比較から除外する。

同一結果の許容誤差や除外基準も実験設定である。シミュレータ状態を利用した場合は、追加の教師情報として明記し、同じ基準を対照条件にも使う。

## 10. 最終目的関数

比較する未来距離の集合を、例えば

$$
\mathcal H=\{1,2,4\}
$$

とする。これはモデルステップの候補設定であり、最適値と確認されたものではない。

撮影条件の順序付き組v→w、未来距離H、実験グループについて損失を平均し、

$$
\boxed{
\mathcal L_{\mathrm{ours}}
=\mathbb E_{g,H,v\ne w}
\left[
\mathcal L_{\mathrm{pred}}^{g,v\to w,H}
+\lambda\mathcal L_{\mathrm{cross}}^{g,v\to w,H}
\right]
}
$$

とする。

**平均するのはスカラーの誤差・識別損失であり、異なる物体配置の潜在表現や未来を平均して一つの教師にするわけではない。**

### SIGRegの扱い

- 本命候補：上記の二項。SIGRegを入れない。
- 併用対照：同じ構成にSIGRegを残す。
- その他の対照：同じデータ上で元LeWM、時間中心化正則化、逆力学型対照学習、通常の未来対照予測を比較する。

ガウスを除くこと自体が研究の成功条件ではない。必要な情報の保持、予測、制御、外乱下の性能を改善できたかで判断する。

## 11. 学習手順

### 11.1 分岐データを収集する

1. 同じロボット・同じ制御形式で、複数タスク由来の短い行動列を集める。
2. 操作対象外の物体位置など、後続操作に必要な要因を変えた初期状態を用意する。
3. 各初期状態を復元し、各行動列を実行して物理軌道を記録する。
4. 同じ物理軌道を複数の撮影条件で観測・再描画する。
5. 同一結果と識別不能な比較の扱いを、学習前に定める。

初期状態の復元には位置だけでなく、速度、接触に影響する内部状態、制御器状態、必要な履歴などの整合も必要である。安全でない行動を実機で無差別に交差実行せず、最初はリセット可能なシミュレータで検証する。

### 11.2 一回の学習更新

1. 複数の対応表を、タスク・状態・行動の偏りを抑えて選ぶ。
2. 入力と教師用の二つの撮影条件を選ぶ。
3. 履歴画像・実測未来画像を共有Eで潜在化する。
4. 共有AとFで、各行動列について自己回帰的に未来を予測する。
5. 撮影条件をまたぐ予測誤差を計算する。
6. 同じ対応表の全未来候補に対して識別損失を計算する。
7. 逆方向の撮影条件でも計算し、複数の未来距離を平均する。
8. E・A・Fを同時に更新する。

### 11.3 擬似コード

以下は処理順序を示す擬似コードであり、公式LeWMへ接続済みの実行スクリプトではない。

```python
# 一つの対応表: B = Ns * Na 個の物理軌道
# context[v]: 各マスの観測履歴。形状 [B, m_ctx, C, Himg, Wimg]
# future_actions: 実行した行動ブロック列。[B, Hmax, action_dim]
# action_history: 初期履歴のフレーム間で実行した行動ブロック。
# actual_future[v][h]: hステップ先の実測画像。[B, C, Himg, Wimg]
# positive[h]: 同一結果の対応。[B, B] の真偽行列。対角は必ずTrue。

optimizer.zero_grad(set_to_none=True)
queries = {}
targets = {}

for v in selected_views:
    z_context = normalize(encode(context[v]))

    # 実際の未来画像は入力しない。直近の予測を再入力する。
    # 履歴の行動と、現在フレームから出る最初の未来行動を混同しない。
    queries[v] = rollout(
        z_context,
        action_history,
        future_actions,
        normalize_each_step=True,
    )

    targets[v] = {
        h: normalize(encode(actual_future[v][h]))
        for h in horizons
    }

terms = []
for v, w in ordered_distinct_view_pairs:
    for h in horizons:
        q = queries[v][h]       # [B, D]
        y = targets[w][h]       # [B, D]; 教師側にも勾配を流す

        pred_loss = ((q - y) ** 2).sum(dim=-1).mean()
        distances = ((q[:, None, :] - y[None, :, :]) ** 2).sum(-1)
        logits = -distances / temperature

        # 実装ではlogsumexpを用い、expの数値的なオーバーフローを避ける。
        positive_logits = logits.masked_fill(~positive[h], -float("inf"))
        log_numerator = torch.logsumexp(positive_logits, dim=1)
        log_denominator = torch.logsumexp(logits, dim=1)
        cross_loss = -(log_numerator - log_denominator).mean()

        terms.append(pred_loss + lambda_cross * cross_loss)

loss = torch.stack(terms).mean()
loss.backward()
optimizer.step()
```

候補順序を並べ替える場合は、教師yと正例マスクの列を同じ順で並べ替える。上の予測誤差は元の一対一対応を保って計算する。複数グループでは、グループ間を混ぜずにこの計算を行って平均する。

## 12. 数学的に期待できることと、保証できないこと

### 12.1 初期状態の違いを消した場合

異なる初期状態を同じ潜在履歴へ写すと、同じ行動列に対する決定論的予測器は同じ予測qを返す。

実測未来の潜在表現y1とy2が異なるなら、

$$
\frac12\bigl(\|q-y_1\|^2+\|q-y_2\|^2\bigr)
=\left\|q-\frac{y_1+y_2}{2}\right\|^2
+\frac14\|y_1-y_2\|^2
$$

である。したがって平均予測誤差には、

$$
\frac14\|y_1-y_2\|^2
$$

という下限が残る。

この式は、**未来側の必要な違いが保持されている限り、初期状態側にも予測に必要な違いが必要になる**ことを示す。未来側も同時に学習されるため、この不等式だけで非崩壊が保証されるわけではない。識別損失が未来側の同一視に代償を与える。

### 12.2 完全崩壊した場合

B個の候補がすべて同じ表現になり、正解が一つなら、

$$
\mathcal L_{\mathrm{cross}}=\log B
$$

となる。B=4ならlog 4である。正例がp個なら、その行の損失はlog(B/p)になる。

これは定数表現が識別に失敗することを示すが、**崩壊点から必ず脱出する証明ではない。** 完全崩壊点が勾配ゼロの停留点になることもあり得る。全次元の情報保持、意味の正しい分解、未知環境への一般化も保証しない。

### 12.3 撮影条件との分離が成立する前提

観測をo = R(s, nu)、物理状態変化をs' = f(s,a)と書く。nuは照明・カメラなどの条件である。

目指す関係は、

$$
E(R(s,\nu))\approx\phi(s)
$$

$$
F(\phi(s),a)\approx\phi(f(s,a))
$$

である。ただし、phi(s)は履歴から識別でき、評価対象の操作に必要な状態を表すものとする。

一方のカメラでは青の位置が見え、もう一方では完全に隠れるなら、両画像から同じ詳細状態を一意に復元できるとは限らない。無条件な一致強制は、見えている側の情報まで消す可能性がある。

したがって最初は、必要な物体が両視点から見える条件を対象にする。遮蔽は履歴・追加視点・不確実性表現などの別課題として扱う。

### 12.4 残る抜け道

- 比較表の有限個のマスだけを識別し、一般的な物理状態を学ばない可能性。
- 行動が接触前の短い区間で、行動差と物体差が十分に結果へ現れない可能性。
- 正例判定が粗すぎて必要な違いを消す、または細かすぎて不可観測な違いを分離させる可能性。
- 特定の背景・タスク頻度・ロボット姿勢などを使う近道。
- 少数次元だけで比較を解き、後続操作に必要な情報は不足する可能性。
- 試した行動列では結果へ現れない情報を失う可能性。

**二乗誤差や識別精度だけで成功とせず、未学習配置・後続制御まで評価する。**

## 14. 推論時の処理とGoalの役割

推論では、撮影条件の異なる対応表や実測未来は不要である。

```text
現在の画像履歴
      │
      ▼
共有Eで潜在化・正規化
      │
      ▼
CEMが生成した行動候補を共有A・Fで未来展開
      │
      ▼
全手法共通のGoalコストで採点
      │
      ▼
先頭の短い行動区間を実行し、再観測して再計画
```

Goal画像を使う評価なら、それは「こういう状態になってほしい」という参照画像であり、実際に将来撮られる写真ではない。参照Goalも同じEとNで処理する。

$$
J(\mathbf a)=\|\hat z_H(\mathbf a)-z_{goal}\|^2
$$

を最初の共通コスト候補とする。正規化は距離の性質を変えるため、正規化の有無だけを変えた対照も必要である。

**この学習方法だけでタスク指示が不要になるわけではない。** 実行時には参照Goal、登録タスクの目標、または別に定義された指示が必要である。言語理解を自動的に獲得する方法ではない。

参照画像が箱内位置まで要求してしまう問題や、意味的な成功集合の扱いも、この予測学習だけで解決済みとはしない。

## 15. 中長期タスクとの関係

中長期タスクは、本手法の情報保持と再利用性を評価する場である。

```text
学習する経験：赤を操作する／青を操作する／把持・解放する

評価する組み合わせ：
赤を片付ける → 青を片付ける
青を片付ける → 赤を片付ける
赤を箱に入れる → 箱から再び取り出す
```

赤を動かす間に青の位置を失わないこと、箱入れの成功後にも取り出しに必要な位置情報が残ることを調べる。

最初から新しい高位世界モデルやチェックポイント生成器を追加しない。サブゴールが必要な評価では、**同じ参照画像・同じ段階切替・同じ計画予算を全手法へ与える。**

短い複数時刻先の学習だけで、数分間の計画、記憶、失敗復旧が解決するとは主張しない。それらは別途必要になる。

## 16. 計算量とデータ収集の負担

### 16.1 推論

大きな追加ネットワーク、逆力学ヘッド、画像デコーダは使わない。追加は主に潜在正規化である。視点違いの画像を推論時に何枚も作る必要はない設計とする。

ただし、実際の遅延・成功までの再計画回数は測定する。正規化や学習結果が計画性能へ影響し得るので、実行時間が完全に同一とは断定しない。

### 16.2 学習

一つのグループにB軌道、V撮影条件、比較距離集合Hがある場合、全順序付き撮影条件対で距離を計算する単純実装の識別部分は概ね、

$$
O\!\left(|\mathcal H|\,V(V-1)B^2D\right)
$$

となる。比較行列は、各時刻・各視点対につきB×Bであり、ミニバッチ全体の画像数の二乗にする必要はない。

各入力視点の予測は一度だけ最大予測距離まで展開し、途中の予測を複数のH・教師視点で再利用する。未来距離ごとに最初から展開し直さない。

学習負担の主な増加要因は、比較行列よりも以下である。

- 撮影条件を増やすことによる画像エンコード。
- 複数入力視点からの未来展開。
- 複数ステップへの逆伝播で保持する中間値。
- 物理的な分岐試行と再描画、保存容量。

同じ物理サンプル数のまま二視点を両方エンコードすれば、その画像エンコード部分は一視点の場合の概ね二倍になる。学習全体が必ず二倍という意味ではない。片方向ずつの学習や画像の再利用で削減する余地はあるが、実測が必要である。

### 16.3 実機と個人実験

最初は小さなリセット可能シミュレーション、同じロボット・同じカメラ系、二つの操作対象から始める。自由な実機リセットや大量の分岐試行は前提にしない。

既存のオフライン動画だけでは、記録されていない「同じ初期状態×別行動」の実測未来は得られない。モデルの生成未来で置き換えると別の手法になり、実測による根拠を失う。

## 18. 評価とデータ漏洩対策

### 18.1 評価軸

| 評価 | 検証対象 |
|---|---|
| 標準撮影条件での各タスク | 元の制御性能を落としていないか |
| 未学習の照明・背景 | 外観変化で破綻しないか |
| 未学習のカメラ位置・画角 | 可観測範囲内で予測・制御できるか |
| 照明と視点の組み合わせ変更 | 学習した変動を組み合わせられるか |
| 未学習の初期配置×行動 | 対応表の記憶で終わっていないか |
| 赤→青、青→赤などの後続操作 | 非操作対象の状態を保持しているか |
| 物体位置・把持状態の読み出し | 何の情報が潜在表現に残ったか |
| 複数ステップの実測未来識別 | 未来展開で情報が消えないか |
| 学習時間・メモリ・計画遅延 | 個人で扱えるコストか |

照明変更の前後で表現が同じという指標だけでは、すべてを同じにする崩壊でも高評価になり得る。**外乱への一致と、物理状態の識別・実際の制御を同時に測る。**

完全遮蔽、未知の重量・摩擦、大きな視点変更で新しく現れる物体は、別の条件として報告する。

### 18.2 分割

同じ初期スナップショットから派生した行動分岐、同じ物理軌道の再描画、同じ元画像の拡張を、学習と評価へ分散させない。元の物理実験ファミリー単位で分割する。

カメラ・照明の評価範囲も独立に定義する。同じ軌道を別視点で再描画しただけのものを、未知の物理軌道への一般化と呼ばない。

複数の乱数初期値、タスク別結果、平均だけでなく劣化したタスクも報告する。

## 19. 関連研究と新規性の位置付け

LeWMの二項学習が出発点である。[1] 未来予測に画像拡張を組み合わせるSPR、複数視点を使うMV-MWM、負例選択を検討する研究が存在する。[2][3][4] したがって、**未来の対照予測、画像拡張、複数視点対応を初めて提案したとは主張しない。**

AC-MTMは、実行行動を遷移から識別する学習用の逆力学分岐を用いる。[5] 本案の教師は行動ラベルの復号ではなく、交差実行した条件に対応する実測未来である。ただしこの差分だけで新規性が確定するわけではない。

時間中心化SIGRegは、持続成分と時間残差への分散配分を変更する比較対象である。[6] 論文の下流方策学習の結果を、そのまま同じCEMでの世界モデル計画性能と比較しない。

### 新規性の候補

**複数タスク由来の行動を、後続操作に必要な状態差を持つ初期条件へ交差適用し、さらに同じ物理結果を複数の撮影条件で観測する。その対応を利用して、状態・行動に必要な識別と、撮影条件への頑健性を一つの軽量LeWMの学習へ組み込むこと。**

これは検証すべき差分候補であり、網羅的な先行研究調査を完了した宣言ではない。

### 主張を認める条件

同じデータ・容量・計画器と、明記した計算予算で、通常の対照予測や既存の正則化より、非操作対象の情報保持、未学習の配置・行動の組み合わせ、外乱下の後続制御が改善すること。

同じデータを通常の方法へ与えるだけで改善が再現するなら、交差対応を利用した学習の独自の効果は弱いと判断する。SOTAは実験後に、対象範囲と評価条件を限定して主張する。

## 20. 人動画と今後の拡張

人動画は現在の実験には含めない。

将来、視覚エンコーダの事前学習に使う余地はある。ただし本手法の中心である「同じ初期状態に複数のロボット行動を適用した実測未来」は、関節・手先指令を持たない任意の人動画からはそのまま得られない。

人動画を使う場合は、別の事前学習課題または行動対応付けを明示する。現在の交差実測損失だけでLeWM全体を人動画から事前学習できるとはしない。

中長期タスクの高位計画、部分観測の記憶、視点ごとの可観測情報の分離などは、基本案の効果を確認してから追加検討する。

## 23. 研究概要

> 本研究では、複数タスクの経験を一つの軽量LeWorldModelへ統合するため、初期状態と継続行動を交差させた実測未来に基づく学習を検討する。同じ行動でも初期状態が異なれば結果が変わり、同じ初期状態でも行動が異なれば結果が変わるという対応を利用し、現在の操作対象以外の情報も保持する共有表現と予測器を学ぶ。さらに同じ物理軌道を照明・カメラ条件を変えて観測し、異なる撮影条件の間で未来予測と実測未来識別を行う。全潜在分布の等方ガウス化を本命候補から外し、実測された物理状態差の保持と撮影外乱への頑健性を両立できるかを検証する。中長期タスクは、共通の計画器の下で後続操作への情報再利用を評価する場とする。

**現段階の成果は、この仮説と比較条件を具体化した設計書である。学習成功・非崩壊・頑健性・計算上の優位性を実証したものではない。**
